# Decisions beyond BLUE_BUILD_PROMPT.md

Answers given during the build. When these and the prompt disagree, these win.

| Date | Topic | Decision |
| --- | --- | --- |
| 2026-11-17 | SIM choice | No READ_PHONE_STATE. The picker lists SIM ids seen in the inbox, with slot number and top senders. |
| 2026-11-17 | SIM choice | Several ids can be ticked. Android can give the same SIM a new id over time, and SMS restored from a backup have no id (-1), which is a tickable option. |
| 2026-11-17 | Foreign currency | Non-INR amounts (e.g. "USD 99.00" on the HDFC card) get no amount. The user types the rupee amount in Review. |
| 2026-11-17 | Banks | Parse every bank and card seen, not only the four in the prompt: also SBM OneCard, Axis, Kotak, Unity, AU, and Jupiter's own SMS. |
| 2026-11-17 | HDFC AutoPay | "AutoPay (E-mandate) Success!" SMS are `ignore`. The matching "Spent"/"Amount Spent" SMS makes the card. |
| 2026-11-17 | Starred SMS | Any SMS can be starred. Starred SMS are listed together in a Starred section. Blue never stars on its own. |
| 2026-11-17 | Room table name | `transactions`, because `transaction` is an SQL keyword. |
| 2026-11-17 | Swipe directions | Not in the spec. Swipe right = Confirm, left = Skip. Buttons do the same. |
| 2026-11-17 | Confirm needs amount | Besides category and "for whom", Confirm needs an amount and in/out (needed for USD cards). Missing any opens the edit view. |
| 2026-11-17 | Contacts | Uses the system contact picker, which shares only the picked contact. No READ_CONTACTS prompt is needed. The name is stored so it survives the contact being deleted. |
| 2026-11-17 | Suggestions | Category: exact-merchant memory, else "Refund" for refunds, else none. For whom: memory, else Me. |
| 2026-11-17 | Undo | Undo covers Confirm, Skip, Duplicate, Not a transaction and Back to Review (last 2). Plain edits saved with Save are not undo steps. |
| 2026-11-17 | Insights periods | Week runs Monday–Sunday. A period still in progress is compared like for like: 1–17 Nov vs 1–17 Oct, this week so far vs the same days last week, today vs yesterday. A finished month is compared with the whole previous month. Custom ranges are compared with the same number of days just before. |
| 2026-11-17 | Insights totals | Uses each entry's saved category. Pending cards with only a suggestion count as "Uncategorised" until confirmed. Entries without an amount (USD not filled in) are left out and counted in a warning. |
| 2026-11-17 | Transactions list | Defaults to All time and "Counted" (everything except duplicates and non-transactions), so its totals match Insights. "Not counted" shows duplicates and non-transactions. |
| 2026-11-18 | Upcoming matching | Money items close on the first debit whose merchant's first word matches (one may be a prefix of the other, at least 4 letters), within the item's amount (the maximum for mandates), and not more than a day older than the item's SMS. Parcels close by tracking number, else the oldest open parcel from the same sender. Closing SMS also close proposals not yet accepted. |
| 2026-11-18 | Investment pre-fill | The spec says money items' debit cards get category Investment. Applied only to SIPs: typical mandates and auto-debits are app stores and subscriptions, where Investment would be wrong. Those cards use merchant memory instead. |
| 2026-11-18 | Spam | Spam is grouped by sender header (e.g. HDFCBN). "Not spam" marks that sender's flagged SMS as ignored by you; re-running rules never overrides it. Removing a sender from the spam list sends its SMS back to "To confirm". |
| 2026-11-18 | Gemini model | Default `gemini-3.1-flash-lite` ($0.25 / $1.50 per 1M tokens, Nov 2026). `gemini-2.5-flash-lite` is cheaper but Google limits it to existing users. Editable in Settings. |
| 2026-11-18 | Gemini API | Uses the Interactions API (`/v1beta/interactions`), which Google now recommends over `generateContent` (legacy). Sends `store: false` and `thinking_level: minimal`. |
| 2026-11-18 | Gemini scope | Gemini gets: SMS the rules couldn't classify, and rule-made pending cards (refilled field by field; Gemini's nulls keep the rule value). Confirmed and hand-edited cards are never refilled. If Gemini says a rule-made card isn't a transaction, the card stays and shows that note. |
| 2026-11-18 | Gemini failures | Bad key/model/billing pauses the whole queue (shown in Settings) without using up any SMS's tries. Offline/rate limits retry later. A bad reply for one SMS counts toward its 3 tries; "Process with AI" always runs regardless. |
| 2026-11-18 | Google scopes | Only `drive.file` (files Blue creates). It covers the backup file and Sheets that Blue creates; no broad Sheets or Drive scope. Uses Google's AuthorizationClient; no client id in the app (Google matches package + SHA-1). |
| 2026-11-18 | Backup | One visible file, "Blue backup.json", in My Drive, overwritten on each backup. Contains all tables and settings, never the Gemini key. Restore replaces everything after a confirmation and clears undo history. |
| 2026-11-18 | Sheets export | Each export makes a new spreadsheet "Blue export <date time>" with one row per entry (all statuses), every field, and the SMS text. |
| 2026-11-18 | Release key | Created now so both SHA-1s go into Google Cloud at once. Lives in `release/blue-release.jks`, password in `keystore.properties` (both git-ignored, never committed). Losing it means release updates need an uninstall. |
| 2026-11-18 | UI redesign | Restyled to the Claude Design canvas (https://claude.ai/artifact/FDrA6uZaaLFsQwxLsHLZc5): calm, mostly black/grey on white; blue only for the main button and the selected-tab dot, green only for money in; selected chips black; Inter + Space Grotesk (bundled, OFL); plain rows with thin dividers. The Transactions tab is labelled "Entries". Home adds "₹X by this time last month" from real data. UI only: no behaviour changed. |
| 2026-11-18 | Daily automatic scan | On by default at 8:00 PM; time and on/off set in Settings. Each run reads SMS since the last scan (last scan date + 2 days of overlap, 2–60 days; 7 days if never scanned). Already-stored SMS are skipped by their unique provider `_id`, so manual Scan and the daily scan never double up. Runs through WorkManager, rebooking itself after each run. The app now opens on Review. Battery optimisation can delay it, so set Blue's battery use to Unrestricted. |
| 2026-11-18 | UI round 2 | "Out/In" and "Money out/in" now read "Spent/Received" everywhere. Home leads with "Review N entries"; scanning is a small "Scan now" row (manual range lives in Settings). Review card is raised on a grey page with the next card peeking; no swipe hint; counter reads "N left". Entries shows every entry with no totals line or status filter (Insights drill-downs still list only counted entries). Insights sections are grey panels with share bars; "By payment method" became "Paid from", one row per account/card named plainly ("HDFC credit card"), last 4 digits only when two would read the same. Times are 12-hour. |
| 2026-11-18 | Swipe and logo | Swiping shows the next card underneath, rising as the top card leaves; the top card tints green with a "CONFIRM" stamp (right) or orange with "SKIP" (left), then flies off. Cards carry a very faint accent gradient. App icon: an italic geometric B whose stem ends in a small loop, white on the accent blue (user picked from 12 options). Swipe feedback is tint only, no words. |
| 2026-11-18 | SMS choice | The SIM-id checklist is replaced by "Which SMS to read": "All SMS on this phone" (recommended; no SIM filter, so old ids and restored SMS are included, stored as a sentinel) or "Only SIM N" for each SIM in the phone. Settings shows "All SMS" / "SIM 1 only". |
| 2026-11-18 | 1.1.0 additions | **Nicknames:** separate `merchant_alias` table keyed by the bank's merchant name (or UPI id); the bank's name is never changed and stays visible under Details, in the edit view and in its own export column. Insights groups by nickname. **Own transfer:** new status `INTERNAL_TRANSFER`, kept in Entries but out of every total; undoable. **Location:** optional "Save where I pay" (off by default) needs RECEIVE_SMS and "Allow all the time" location. On arrival Blue runs its rules on the SMS; payments and undecided SMS get a location saved in `pending_location`, matched to the stored SMS at the next scan by sender + text hash (±15 min) and moved onto the entry; other classes drop it; leftovers are deleted after 3 days. Marking Not a transaction or Duplicate deletes the entry's location (Undo restores it). Gemini can't supply location (SMS carry none), so entries without one offer "Find on Google Maps" by name. **Edit screen:** its Details section (merchant, nickname, account, method, date, time, UPI id, reference, refund, place) folds to a one-line summary; open/closed is remembered while Blue runs. The review card itself is unchanged (a collapsible card was tried in 1.1.0 and reverted in 1.1.1 at the user's request). |
| 2026-11-19 | 1.2.0 privacy masking | SMS sent to Gemini are disguised on the phone first (`SmsMasker`): numbers get random same-length fakes; names become made-up words; UPI ids and links are replaced; IFSC keeps its shape with fake digits; dates, times, bank wording and the sender stay. Words are kept when they are English (bundled public-domain word list), bank/finance terms, used by 4+ senders, or a sender's own boilerplate (learned on the phone from its SMS); non-dictionary words that appear in 3+ senders' greetings (the user's name) are always hidden. Answers are swapped back on the phone; the account's last 4 digits are taken from the masked account number in code. If masking fails, nothing is sent. New Gemini prompt tuned on 20,171 real SMS over 4 rounds with blind Claude review: payment/upcoming/other right 99.76% masked vs 99.84% real text vs 97.37% with the old prompt; wrong entries 448 -> 25. Conventions now in the prompt: OneCard purchase notes are card spends; merchant/biller receipts, refunds not yet credited, collect requests, mandate consent/revocation, demat and EPF notices are ignore; mandates created/active are upcoming. Rule fixes: OneCard purchase notes (and USD ones without amount), HDFC "Money Transfer ... UPI", "AutoPay Active", spends "without OTP/PIN" (a bank transaction format now wins over the OTP guard), SBI NACH credits and UPI mandates created/revoked, more courier wordings; "money transfer", "purchase of" and "payment of" count as money words so unknown formats reach Gemini. Rules alone on the same SMS: wrong decisions 527 -> 180, payments found 3,384 -> 3,695. |
